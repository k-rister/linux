Primary reduction: the old design required 1,539 wrapper-family paths and a kernel-wide *_with_sync_wait() API. The reduced design retains cpu_accel_flush_workqueue(), cpu_accel_drain_workqueue(), and cpu_accel_destroy_workqueue(), and changes 218 producer, teardown, or cleanup call-site files.

The remaining large contributors are intentional: x86 ownership, IRQ quarantine, MMU/TLB/reclaim coordination, SMP and CPU transitions, and the workqueue core. The broad driver conversion is no longer a substitute for identifying sites that can actually wait for work pinned to an accelerator-owned CPU.

Review concentration: the 89 semantic paths carry two-thirds of changed lines and nearly all correctness-sensitive review risk. They concentrate in arch/x86, kernel, mm, and include, plus a small set of required driver fixes.

The reduction is substantive: the removed API eliminated a second exported synchronous-wait naming convention and removed conversions where asynchronous-work completion is not required for accelerator correctness. Remaining workqueue conversions are tied to work production, teardown, cancellation, resource release, or paths that can deadlock against an owned CPU.

Workqueue adoption

The retained call-site family is:

  • cpu_accel_flush_workqueue() for flush-style waits
  • cpu_accel_drain_workqueue() for drain-style waits
  • cpu_accel_destroy_workqueue() for destroy-time waits

The diff adds 536 calls to these wrappers and removes 502 direct legacy workqueue calls across 218 call-site files. The sites concentrate in probe/remove, reset, teardown, module unload, and producer/consumer shutdown paths.

Remaining review obligation: verify each site can execute while an owner is active, preserves the original wait scope, and cannot return from an error path while required work remains unfinished.

Architectural classes

x86 ownership and direct entry

High The backend adds ownership requests, direct user entry, stop and recovery, deferred reschedule/call-function handling, and architecture counters. The dedicated vector and IDT entry are gated by CONFIG_CPU_ACCEL_CORE. Representative paths include arch/x86/kernel/accel.c, arch/x86/include/asm/cpu_accel.h, arch/x86/include/asm/irq_vectors.h, arch/x86/include/asm/idtentry.h, arch/x86/kernel/idt.c, arch/x86/kernel/apic/ipi.c, and arch/x86/kernel/smp.c.

Workqueue core

High include/linux/workqueue.h and kernel/workqueue.c implement the three retained wrappers and prevent new work from being scheduled on an owned CPU.

SMP, CPU transitions, and stop-machine

High Maintenance windows and synchronous remote execution coordinate with CPU online/offline, stop-machine, and freeze/thaw. Representative paths include kernel/smp.c, kernel/cpu.c, kernel/stop_machine.c, and include/linux/smp.h.

IRQ quarantine

High kernel/irq/accel.c, kernel/irq/chip.c, and kernel/irq/manage.c reserve owned CPUs from new affinity assignments, migrate active IRQs, validate effective routes, and restore affinity during rollback.

MMU, TLB, and reclaim

High Memory-management paths coordinate ownership with TLB shootdowns, MMU gather batches, rmap, reclaim completion, vmalloc, and SLUB. Representative paths include arch/x86/mm/tlb.c, mm/mmu_gather.c, mm/rmap.c, mm/vmscan.c, and arch/x86/mm/pat/set_memory.c.

Debug, tracing, and executable memory

Medium Debugger, kprobe, ftrace, jump-label, alternative, MTRR, cache-info, and ring-buffer paths coordinate operations that send IPIs or require a CPU rendezvous. Representative paths include kernel/debug/debug_core.c, kernel/kprobes.c, kernel/ftrace.c, arch/x86/kernel/alternative.c, and kernel/trace/ring_buffer.c.

Required driver-specific fixes

Medium The driver remainder includes target-core TMR handling, Greybus release-path deadlock prevention, and BCM PHY PTP work draining. These change shutdown or error ordering and require subsystem-aware review.

Build and disabled-config boundaries

Medium The x86 public API, dedicated vector/IDT entry, and MMU-owner hooks are gated or backed by no-op stubs when CONFIG_CPU_ACCEL_CORE is disabled, keeping the blast radius conditional.

Review priorities

  1. Ownership state machine: activation, stop, rollback, manager death, owner exit, and recovery must never strand a CPU or admit an unsafe owner.
  2. x86 entry and exception safety: direct entry, NMI/MCE visibility, vector use, and deferred reschedule/call-function behavior require architecture review.
  3. IRQ quarantine: verify affinity reservation, migration, effective-route validation, rollback, and hotplug interaction.
  4. MMU/TLB/reclaim: validate lifetime, shootdown completion, generation handling, deferred batches, and reclaim ordering.
  5. SMP and CPU transitions: prove no deadlock or missed rendezvous when ownership intersects stop-machine, freeze, online/offline, or synchronous IPI waits.
  6. Workqueue semantics: audit all three wrappers and every class of call-site conversion, especially error and destroy paths.
  7. Driver-specific ordering: review target TMR, Greybus release, and BCM PHY PTP changes with subsystem maintainers.

Explicit boundaries

Prototype boundary: this work provides CPU execution ownership and coordination, not device or DMA ownership, and it does not control NMIs, SMIs, machine checks, or arbitrary firmware activity.

It does not provide a formal hard latency bound. It reduces and measures asynchronous kernel interference, but worst-case behavior still depends on firmware, hardware events, and paths outside the ownership contract.

The reduced workqueue footprint is a review-scope improvement, not a claim that all 218 call sites are trivial. Each still needs confirmation that its original synchronous-work guarantee is preserved.
